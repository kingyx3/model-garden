# Tier 0 runtime and autonomous tenant identity (v0.8.235)

The local operator commands for artifacts, memory, unanswered questions, notification preferences, CRM synchronization, conversations and subject-access exports must use the **exact** compiled `source.client` slug or an explicitly supplied, trusted `--tenant`. They never normalize an arbitrary name or silently route missing/corrupt identity into a shared `default` namespace. The customer mailbox ingress already follows this fail-closed rule.

Before upgrading, check that `MODEL_GARDEN_DESIRED_STATE` points to the correct compiled client workspace and contains a lowercase slug (letters, digits, hyphens; maximum 63 characters). An absent, unreadable, invalid JSON or malformed identity stops the command before store initialization or mutation. For operator-approved offline recovery, pass `--tenant <exact-client-slug>` after independently confirming the mounted volume and deployment identity; do **not** use a guessed slug to work around a broken mount. Never point two clients at one data volume. Existing legacy `default` data is **not migrated or renamed automatically**: isolate, inventory and reconcile it with client ownership before any transfer.

These CLIs are not public Agent Tools. Explicit tenant selection does not authenticate a client owner or requester, does not enforce provider-side identity and is not live tenant proof. Retain original live access, retention, audit and consent gates on #77, #109, #115 and #241.

## Autonomous Tier 0 writes (v0.8.235)

The governed `kb.search` no-match recorder and voice-to-CRM filing/timeline path now use the same exact compiled `source.client` slug. An absent, mixed-case, malformed or overlong value is **not** converted to `default` or another tenant. The optional unanswered-question note is skipped rather than failing the customer's answer; the autonomous voice filing command refuses the entire pass **before opening CRM state, generating summaries or recording timelines**. A valid compiled slug continues to use its own tenant namespace.

Upgrade/recovery: verify the deployed desired-state mount and exact client slug before restarting governed Tools or replaying voice filing. A refused pass is not a successful CRM filing; repair the compiled identity, inspect pending voice evidence and retry idempotently. Do not rename or bulk-merge old `default`/normalized files: quarantine them and reconcile ownership and retention with the client. This is host-local identity routing safety, **not** proof of independently scoped SaaS credentials, live SIP calls or client signoff. See #77, #107, #115 and #117.

## Channel gateway and autonomous worker (v0.8.236)

Both the inbound channel gateway and scheduled/background worker now reject a missing, malformed, mixed-case, normalized or overlong compiled `source.client` before opening Tier 0 state. The shared `tenant_from_compiled` resolver is used on the in-memory desired state, so neither service can silently select the old shared `default` tenant. This also covers worker schedule/mailbox/CRM/notices and gateway web-chat/approval/handoff paths; no partial service startup is allowed for an invalid tenant. Malformed capability-manifest client identity remains an unavailable Skill-status response, not an authorization bypass.

**Upgrade:** ensure the deployed desired-state mount contains the exact lowercase client slug and matches the tenant's volume before starting either service. A missing client slug in the bundled developer example must be explicitly supplied by the test fixture or the real client workspace. Do not automatically rename or merge any historical `default` or normalized files; quarantine, attribute, and reconcile them with the client and retention policy. If startup refuses, repair the compiled state, then restart the service and reconcile pending jobs/inbound receipts before retrying. This is credential-free, host-local routing protection, **not** evidence of a deployed tenant, provider-side credential isolation, external receipt, or client acceptance. #77, #115 and #117 remain subject to their original live criteria.
